# Muse 工具消息通道（实验，本机已启用）

## 目标和边界

仅替换同轮 PC 工具请求/结果的文件轮询，保留浏览器登录、Muse 会话、Codex 工具审批与执行。
模型本身思考、云端工具排队和客户端审批耗时不属于传输优化能消除的时间。

链路：云端 `pc.py` 发出一个 HTTPS 请求并等待真实结果 → 独立中继 → 本机已连接的 WebSocket → Codex。
结果原路返回。云端无需新依赖；本机和中继使用独立 Python 环境。无需本机公网入站端口。
任务 manifest、工具说明仍使用云端文件缓存；**命令及执行结果不再读写文件，也不做 0.25 秒轮询**。
聊天状态仍由唯一的后台读者检查，不与逐条工具传输串行。

VPS 并非理论上的必需条件；当前尚未验证原生网关支持自定义可靠双向通道，因此采用用户授权的独立中继。
现有网关的文件订阅即使可用，也不等于去掉文件交接。

## 安全语义

- 中继不执行工具，不开放任意命令执行接口。
- HTTPS/WSS 验证证书；管理员、PC、云端使用不同权限的凭据。
- 每轮独立随机身份、顺序编号、截止时间；一轮只允许一个在途请求，最多 64 次。
- 已用请求编号拒绝再次提交。断线、超时、状态不明不自动重放，不切回文件协议重新执行。
- PC 仍检查本轮用户消息已被确认；后台保留结束/失败检查。
- 两段 TLS 在用户自己的中继终结，中继能看到消息；这不是端到端加密。凭据和消息不写访问日志。
- 服务重启会丢失在途交换；不得根据超时猜测动作未执行。

### 当前连接策略

- 命令/结果通过网络推送，已取消文件交换及其 0.25 秒轮询。
- `Exchange.watch` 仍在活动生成轮次每秒查询聊天状态，用于本轮确认、完成/失败检测；不能称整个系统完全无轮询。
  它不负责通过文件发现每条命令；首条工具交付仍需等待本轮用户消息确认。
- Push 模式不再以 `PC_CONNECTION_IDLE_SECONDS=300` 主动关闭已使用的原生网关。
  健康连接保留到会话缓存淘汰（现有上限 128 个响应快照）或服务关闭；等待审批/执行时也不设五分钟断线计时。
  新用户任务提交前若只读预检发现断线，可以重新建链。任务、工具结果和中继房间的有效期仍然生效。
- 备用中继通道也以 300 秒为未使用回收时间；已领取的通道不重新入池，另有每轮有效期。
  尚未绑定任何任务的备用连接失效时，仅在领取时尝试一次新建；不重放已分配房间或在途命令。
- 云端 `pc.py` 的多次进程调用通过私有 Unix socket 交给同一任务的常驻 `persistent.py`，复用同一 HTTPS 连接。
  socket 目录仅当前用户可访问；启动及所有权文件锁不包含命令、结果或凭据。没有新增公网监听或云端依赖。
  连接遵循 VM 的 CONNECT 出网代理，保留 TLS 校验和权限检查；不支持的代理明确失败，不尝试绕过。
  发送前发现旧连接已关闭，或空闲后的只读 `/health` 检查失败时，可重新建立连接后发送尚未发送的动作。
  命令发送开始后，任何断线/超时都不自动重发；结果不确定时结束该交换，不切回旧协议。
  常驻进程到本轮 manifest 截止时间退出；没有 0.25 秒文件轮询、周期重连或定时五分钟换连接。

它包含逐次建 HTTPS 连接等开销，不包含模型思考、云端 runner 启动/排队、审批或本机执行。

## 显式准备与运行

新环境（不会启动服务或改网络）：

```powershell
.\tools\prepare_muse_web.ps1 -Push
$env:PYTHONPATH = 'native-host'
.\dist-muse-push\Scripts\python.exe -m fanvpn_bridge.muse_tools_setup --push --skill-name YOUR_UNIQUE_NAME
```

安装中继须先核对指定 VPS、端口、证书及路径；`tools/muse_push/install_relay.py` 仅在 Linux 服务端显式运行，拒绝覆盖现有安装。
中继依赖见 `tools/muse_push/requirements-relay.txt`，不会安装进现有代理服务环境。

隔离验收（新增测试会话，只允许两次确切的只读 `hostname`，不替换运行中的服务）：

```powershell
.\dist-muse-push\Scripts\python.exe tools/muse_push/verify.py --tool-workspace workspace/custom-skills/YOUR_UNIQUE_NAME
```

通过验收并确认无在途请求后，才可停止经核验的旧 Muse 独立进程，启动同一端口的新服务：

```powershell
.\tools\start_muse_web.ps1 -Push -ToolWorkspace workspace/custom-skills/YOUR_UNIQUE_NAME -RelayConfigPath "$env:LOCALAPPDATA\FanVPNBridge\muse-web-auth\push-relay.json"
```

回退只需停止经核验的 push 服务，再以原 Python 环境、原 workspace 和 `-PC` 启动旧文件交接服务。
不得在工具执行状态不明时切换协议来重发动作。无需更新 Native Host。
