# Muse 同轮 PC 工具接入（实验，需显式启用）

这是 `muse-web/default` 的另一条工具交接路线，不增加另一份模型目录，不自动替换已有服务。
本机部署需用户授权；研究、编译和临时测试不代表已部署。最新授权部署记录见下文。

## 新包提供的依据

研究对象为用户提供的 `new-muse-onboarding` 包和 `muse-bridge-1.3.0.vsix`。
只读取说明和实现，没有安装 VSIX、运行随包程序、连接对方 VPS 或读取/使用随包 Token。
新实现不复制对方代码，也不修改 Muse 的 SOUL、MEMORY 或原有插件。

同事的链路是：Muse 云端原生工具调用 `musepc`，经本地守护程序、VPS 中转到 PC 插件；
插件执行后，真实结果原路返回，云端调用才完成。它是远程工具执行器，不是直接供 Codex 使用的模型 API。
1.3.0 包还包含调用标识和去重机制，不能把它的自动重试直接照搬到会产生副作用的工具上。

原接入要求 Muse 提交请求后结束回合，再由下一条消息交付工具结果。
新接入采用同轮等待，但把执行权保留在 Codex，不启用同事插件中的任意命令执行器：

```text
Muse 原生云端工具 → pc.py 等待请求结果
                       ↕ 私有 VM 文件交换
                本机独立 PCSessions 服务
                       ↕ Responses 工具调用/工具结果
                    Codex 审批、执行
```

仍使用已有登录票据、认证回环 HTTP 和私有 VM 文件通道，不需要公网端口或额外 VPS。
工具目录采用内容哈希缓存；模型按需查看定义，不把全部定义塞进每轮任务文本。
它不是向 Muse 平台注册任意原生工具；Muse 仍可能拒绝任务，不能绕过平台权限或额度限制。

## 实现边界

- `muse_pc.py` 独立于原服务。`start_muse_web.ps1 -PC` 才选择它，默认行为保持不变。
- 每个原生回合一个 run；连续调用使用有序编号。一轮只允许一个未返回的工具请求。
- 云端辅助程序同步等结果；云端执行器若先返回运行中句柄，模型需要用其正常等待机制继续等，不能把句柄当结果。
- Muse 的 `completed` 过程消息不等于整轮完成；新服务排除 `metadata.message_kind/recipient=commentary`。
- 工具结果到来时不再发送用户消息，也不创建侧会话。普通下一条消息复用原会话并建立新 run。
- 函数参数、namespace、原始 freeform 分别保真转换。辅助程序只交换文件，不执行命令或补丁。
- 请求独占发布，结果临时文件加原子改名。跨会话、错编号、过期、重复交付和工具变化均明确拒绝。
- 云端结束等待后不投递迟到结果；发送/写入结果不明时不自动重放动作。
- 一个 run 最多 64 次调用；辅助程序默认等待 600 秒，上限 1800 秒。云端工具也有自己的运行限制。
- 暂不支持在等待工具结果的同一请求里夹带新任务文本；明确拒绝，不静默丢弃。需新的 Bridge 构建传递此标识。
- 服务或 Bridge 重启导致待执行快照丢失时，不猜测恢复在途动作。不同侧会话仍可能共享 Muse 账号的长期记忆。

### 本机等待开销优化

PC 模式默认轮询间隔由 2 秒降为 0.25 秒，旧交接服务仍保持原默认值。
同一 run 等待 Codex 工具结果时，以及普通任务完成后，独占保留已认证的云端连接最多 300 秒（5 分钟）。
待返回工具结果仍受原有有效期限制，保留连接不延长工具执行权限或结果有效期。
同一会话在空闲期限内的续聊不重复获取票据、握手或读取辅助程序；过期后正常重新建连。
连接不跨会话共享，也不并行读取同一 Noise 流。
空闲超时、快照淘汰和服务退出会关闭闲置连接。仅空闲过期而未交付结果时，后续正常续接可以新建连接；
已经开始发送或写入结果后出错，仍不自动重连、重发或重放工具操作。工具过期和云端完成检查保持不变。
复用连接在新用户任务的只读历史检查阶段失效时，允许重新建连一次；等待工具结果的续接不走这条恢复路径。

PC 模式使用已实测支持的 `chat.history after_seq`。确认读到与本次提交完全相同的用户消息后，
后续查询跳过该消息及此前历史，仍保留本轮所有 assistant 事件，并以本轮用户消息序号作为回答边界。
尚未确认本轮用户消息时，不交付回答或本机工具调用，避免将上一轮迟到的完成事件误作本轮结果。
不能直接把游标推进到最新 assistant 序号：思考中、完成或失败状态可能在同一序号上更新，
后续过程消息也不能遮住较早回答的状态变化。旧交接服务和其他模型不改变查询方式。

任务转发说明仅描述任务、工作要求和工具用法，不设置 Codex 身份，也不加入身份争论的提示。
仅移除客户端指导开头已知的 `You are Codex...` 身份句；保留其后工作约束、审批规则，以及用户消息和引用原文。
客户端指导是本任务应执行的工作要求，不只是引用背景；Muse 自身权限和安全规则仍有效。
这些优化不包含实时正文转发，也不缩短 Muse 自身生成所需时间。实际提速取决于网络、模型和客户端审批耗时。

首轮优化时离线验证：Muse 相关测试 115 项（含 PC 专项 28 项）、Gemini 回归 49 项、HTTP gateway 集成 43 项通过。
隔离实测会话 `0daada1f-931b-4fb4-b430-372d9529865d` 中，两次只读本机调用及结果续接共用一条连接，
只提交一个云端回合；随后普通消息新建连接，仍在原会话中正确回答。两次调用加后续消息共约 105.2 秒，
两次建连累计约 11.6 秒；这不是与旧实现受控对比的提速结果。另一次实验在工具续接成功后新建连接失败，
随后只读建连检查成功，不能据此承诺网络稳定或固定总耗时降幅。
上述首轮实现随后已按用户要求重启独立 Muse 服务。

### 续聊连接复用和增量历史验证（隔离验收记录）

本轮 Muse 相关测试 121 项（含 PC 专项 34 项）、Gemini 回归 49 项、HTTP gateway 集成 43 项通过。
隔离会话 `e3aa6868-d263-41c6-a281-4723678caf6f` 中，两次只读 hostname 调用、结果回传和紧接着的普通消息
共用一条连接；增量历史已启用，实际结果和同一会话续聊均验证通过。
首次请求进入提交步骤前约 5.505 秒，复用连接的后续消息约 1.272 秒；这是客户端开始调用 `chat.stream`
之前的时间，不是模型已收到消息的时间。整组实测约 40 秒，不作为相对旧实验的受控总耗时对比。
前一次验收在冷连接阶段失败、未提交任务，不能承诺网络稳定或冷启动达到 1 秒内。

对同一个已有对话交替进行三组只读查询，完整历史 JSON 约 186,712 字节，当前轮次历史约 22,834 字节，
减少约 88%；平均查询耗时分别约 1.56 秒、0.76 秒，三组均得到相同终态回答。
保留 0.25 秒轮询空闲间隔，避免无休止查询，不缩短任务超时或取消完成/失败检查。

上述隔离验收时未部署；提速改动位于独立 Muse 服务，随后已按授权重启加载，见下方部署实测。
之前的转发提示词改动仍由 Native Host 加载，不应将两者的部署步骤混淆。

### 5 分钟连接保留：已部署实测

按用户授权，仅重启 `127.0.0.1:8008` 的独立 Muse PC 服务；Bridge、转发代理、Native Host 和网络配置未修改。
Muse 相关离线测试 124 项（含 PC 专项 37 项）通过，覆盖 300 秒空闲定时器、工具原有效期、连接独占和本轮消息确认。
HTTP gateway 集成 43 项通过。Gemini 全部 62 项在已安装 Pillow 的系统 Python 中通过；
Muse 隔离环境缺少 Pillow，首次扩大 Gemini 测试范围时有两项图片测试无法导入依赖，未为此修改运行中服务的环境。

通过实际运行的 Bridge `18888` 新建会话 `a2420a78-70e3-42c4-87db-4f232aa98aae`，
顺序执行两次只读 `hostname`，验证实际结果回传、立即追问及空闲 40 秒后追问，均在同一云端会话中正确完成。

| 测量 | 本次结果 |

| 首次请求发出 → Muse 云端记录用户消息 | 4.764 秒 |

本机命令本身分别耗时 0.0302、0.0255 秒。整组验收 88.9 秒，包含 40 秒主动空闲和模型生成、结果回传、只读观测；
不能把整组耗时当成传输延迟。单向延迟由 PC 和云端时间戳估算，假定双方时钟同步，且样本很少，不承诺固定耗时。
实际验证覆盖超过原 30 秒限制的续聊；5 分钟上限由配置及离线定时器测试验证，未进行完整 5 分钟空闲实测。

此前五次只读调用及最终结果已通过，但随后追问的精确校验未通过；云端历史确认追问及正确回答存在，
当次未保存本地返回文本，不能确定根因。随后补充本轮消息边界保护，并以上述新的两次调用完成复测，未重放原五次任务。

## 2026-10-21 实测

验收使用临时认证回环端口，不接管正在运行的 8008/18888/18889 服务。
云端新增独立测试目录 `workspace/custom-skills/codex_pc_20261021`，没有覆盖旧技能。

最终验收会话：`7ff8e32b-1b19-4d7e-9e6a-5dc8b9ccb799`。

1. Muse 在同一原生回合连续请求两次 namespaced `functions.exec_command`，参数均为 `{"cmd":"hostname"}`。
2. 验收器只允许这个确切的只读命令，以绝对路径、非 shell 方式在本机实际执行，并逐次返回真实输出及执行后生成的随机收据。
3. Muse 收到第二次真实输出并正确回复。两次工具结果均未触发新的 `chat.stream`。
4. 以完整历史、不带 `previous_response_id` 再发一条普通消息，仍在同一云端会话中正确回答。
5. 总耗时约 73.8 秒；仅为这次实验值，不是性能承诺。

前置实验发现并修正了“完成的空白过程消息被当成整轮结束”；另有一次结果交付前连接超时，不能据此宣称网络稳定。
一次正确读回实际输出的实验返回了完整结果 JSON，而非纯 output 文本；验收允许精确匹配原输出或完整结果对象，不接受只包含收据片段。

离线 Muse 相关测试 106 项、Gemini 回归 49 项、HTTP gateway 集成测试 43 项通过。
其中 PC 专项 22 项覆盖同轮连续调用、后续消息、中文 freeform、结果串线、过期、并发和不重放。
**真实验证不是 Codex UI 审批验收**：执行者是受限验收器。未验证完整工具目录/真实开发任务、实际补丁应用、多 agent 长期并发或所有 Muse 安全检查。
Native Host 已独立编译到 `dist-muse-pc/browser-ai-bridge/`，未安装、未重启现有服务、未修改网络。

## 显式切换（仅供用户部署）

先在安全时机按既有流程更新 Native Host。不要让新旧 Muse 服务同时占用 8008。
确认旧 Muse 独立服务的 PID 后，只停止该进程；不要批量停止 Python、Bridge、浏览器或代理。
随后在仓库目录运行：

```powershell
.\tools\start_muse_web.ps1 -PC -ToolWorkspace workspace/custom-skills/codex_pc_20261021
```

新电脑需要先准备隔离环境和浏览器登录，再显式安装一个未占用的独立云端目录：

```powershell
$env:PYTHONPATH = 'native-host'
.\dist-muse-web\Scripts\python.exe -m fanvpn_bridge.muse_tools_setup --pc --skill-name YOUR_UNIQUE_SNAKE_CASE_NAME
```

已有测试目录不要重复安装。回退时只停止新 Muse 服务，使用原来的不带 `-PC` 的启动命令和旧 workspace。
手动重跑真实验收会新增云端测试会话，并仅执行两次确切的本机只读命令：

```powershell
.\dist-muse-web\Scripts\python.exe tools/muse_pc/verify.py --tool-workspace workspace/custom-skills/codex_pc_20261021
```
